# ContinuousPlayer 共通操作仕様案 v1

作成日：2026年10月24日  
更新日：2026年10月27日（アプリ内終了・補助メニュー・追加画面の重複ボタン・一覧の名前確認ボタンを廃止）

状態：提案・未実装  
対象：Android、Android TV、iOS、iPadOS、tvOS、Mac Catalyst、Windows

## 1. 方針と適用範囲

「同じ目的の操作は、どの環境でも同じ結果になる」を共通原則とする。入力機器の違いに合わせて、直接タッチ、ポインター、方向キーの操作方法を定める。端末名だけで操作方法を固定せず、iPadのキーボード、Windowsのタッチ、Androidのマウスにも同じ入力ルールを適用する。

基礎資料：

- [3版のUI・操作比較](./platform-ui-operation-comparison-2026-10-24.md)

「一覧のキャンセルで元の状態を復元」「割り込み後は手動再開」「登録後は保存済み一覧へ戻る」を基本とし、入力競合、状態遷移、TV操作、エラー処理を定める。本書は共通操作の提案であり、各アプリへの実装状況を示すものではない。

### 1.1 共通化するもの

- ファイル選択、再生、一覧への戻り、キャンセル、ホームへの遷移。
- 再生／一時停止、前後ファイル、10秒シークの結果と境界動作。
- フォーカス、モーダル画面、文字入力とショートカットの優先順位。
- 中断・復帰、登録、登録解除、接続失敗時の意味。
- 操作名称、基本のボタン順、状態表示とフィードバック。

### 1.2 環境に合わせるもの

OSのフォルダー許可画面、ウィンドウ枠、全画面のショートカット、文字サイズ・タッチ領域・TV視聴距離に応じた寸法は各環境に合わせる。コーデック、音声出力方式、USB利用可否、DLNA探索権限の一致は別の機能要件とし、同じ画面を表示するために未対応機能を偽装しない。

本案では設定スイッチを増やさず、基本動作を1つに揃える。

## 2. 最優先で揃える7原則

1. ホームから「OP / EDを選ぶ」を押すと、登録数にかかわらず保存済み一覧を開く。
2. 再生中の「ファイル一覧」は再生を一時停止し、現在のフォルダー・ファイルを表示する。
3. 一覧でファイルを選ぶと、そのファイルの0秒から再生する。
4. 一覧をキャンセルすると、元のファイル・秒数・再生／一時停止状態へ戻る。
5. バックグラウンド化・ロック等の割り込み後は、自動再開しない。
6. ←／→は前後ファイル、↑／↓は−10秒／＋10秒。ただしフォーカス中のUIを優先する。
7. ファイル一覧や情報の表示では再生セッションを破棄しない。ホームへ戻る・ウィンドウを閉じる・アプリを終了する場合は終了し、新しいファイルの選択確定時には新しいセッションへ切り替える。

「一覧のキャンセルによる再開」と「割り込みからの復帰」は区別する。割り込みがあった場合は原則5を優先する。

## 3. 共通の画面と名称

| 画面・操作                 | 共通名称・役割       |
| -------------------------- | -------------------- |
| 初期画面                   | ホーム               |
| ホームの主ボタン           | OP / EDを選ぶ        |
| 登録先の一覧               | 保存済みフォルダー   |
| 追加                       | フォルダーを追加     |
| 再生中の一覧ボタン         | ファイル一覧         |
| 詳細情報                   | メディア情報         |
| 再生を終えて初期画面へ     | ホームに戻る         |
| 登録操作                   | このフォルダーを登録 |
| 登録の取り消し             | 登録解除             |
| ファイル選択全体を取り消す | キャンセル           |
| 親階層へ移動               | 上のフォルダー       |

「戻る」を、親階層・キャンセル・ホーム・アプリ終了の共通ラベルに使わない。アイコンだけのボタンにも上表の読み上げ名・ツールチップを付ける。

### 3.1 操作ボタンの構成

- 一時停止時のメニューは、上端・下端の各1行にする。
- 上端の左に、再生中のメディアの拡張子を除いたタイトルを配置する。長いタイトルは1行で末尾を省略し、名前の途中のピリオドや拡張子なしのタイトルは保持する。元の名前はメディア情報で確認できる。
- 上端の右に、ホームに戻る → ファイル一覧 → メディア情報の順でアイコンを配置する。終了・エラーの状態文も上端の同じ行内に収め、タイトルの長さでアイコンを押し出さない。
- 下端中央に、前のファイル → 10秒戻す → 再生／一時停止 → 10秒進める → 次のファイルを1行で配置する。
- 上下の操作部の背景は画面の上端・下端に接地させ、外側に空白を置かない。非表示のシステムバーの高さは予約せず、表示中のバーや切り欠きを避ける余白は操作部の内側に確保する。間の再生領域を追加のメニュー行で覆わない。
- 一時停止・再生終了・エラーでは操作部を表示する。
- タッチ、リモコン、ポインターのいずれでも、ジェスチャーやキーを知らずに主要操作を完了できるようにする。
- 縦長・横長・TVとも上端と下端の配置を保つ。再生と一時停止の切替や回転で、操作部のために映像領域の大きさ・位置を変えない。
- Mac CatalystやWindowsでタイトルバーに上部操作を置く場合も、順序・名称・結果を共通化する。全画面でも操作可能にする。

### 3.2 操作部の表示・非表示

- タッチ：一時停止で表示。中央タップで再開すると再生操作部を隠す。
- ポインター：映像内でマウスを動かすと表示。再生中は操作が3秒なければ操作部とカーソルを隠す。
- TV：一時停止で表示し、再生ボタンにフォーカスする。再開すると再生領域へフォーカスを戻して隠す。
- フォーカスが操作部にある間、ポインターがボタン上にある間、ダイアログ表示中、スクリーンリーダーで操作中は自動で隠さない。
- 音声のみの再生では映像用の自動非表示を適用せず、タイトルと操作部を表示する。
- バッファリングだけを理由に一時停止用の操作部へ切り替えない。

## 4. ファイル一覧とキャンセル

### 4.1 一覧を開く

再生画面の「ファイル一覧」、Esc、Androidの戻る、tvOSの戻るから、同じ動作を実行する。

1. 現在のファイルID、プレイリスト、秒数、再生意図、再生元フォルダーを保持する。
2. 再生を一時停止する。
3. 現在のファイルの親フォルダーを開く。
4. そのファイルを選択表示し、見える位置へスクロールする。
5. TV・キーボードではそのファイルへフォーカスを合わせる。

一覧表示中にフォルダーを移動・登録・登録解除しても、再生セッションは変更しない。新しいファイルの選択を確定するまで元の状態を保持する。登録解除でも元のメディア自体は削除しない。

### 4.2 選択とキャンセルの結果

| 操作                                         | 結果                                                     |
| -------------------------------------------- | -------------------------------------------------------- |
| 別のファイルを選ぶ                           | そのファイルを0秒から自動再生                            |
| 現在と同じファイルを選ぶ                     | 同じファイルを0秒から自動再生                            |
| 一時停止中に一覧を開き、ファイルを選ぶ       | 選択を明示的な再生指示として、0秒から自動再生            |
| 再生中に一覧を開き、キャンセル               | 元の秒数から再生を再開                                   |
| 一時停止中に一覧を開き、キャンセル           | 元の秒数で一時停止を維持                                 |
| 別フォルダーまで移動してキャンセル           | 元のフォルダー・ファイル・プレイリスト・秒数・状態へ戻る |
| 一覧表示中に割り込み、その後キャンセル       | 元の秒数へ戻るが一時停止を維持                           |
| 元のメディアが取り外された／アクセスを失った | 自動再開せず、再接続・再選択を案内                       |
| ホームに戻る                                 | 保持していたセッションも終了                             |

一覧で選択するまで、背景で次のファイルへ進まない。フォルダー移動だけで新しいプレイリストを作らない。

新規ファイルの選択後に再生準備が失敗した場合は、そのファイルのエラーを表示する。黙って元の動画へ戻したり別ファイルへ進めたりしない。

### 4.3 階層移動とキャンセルを区別する

- 一覧内の「上のフォルダー」／Backspace／TVの戻る：1階層だけ上へ移動する。
- 再生可能な登録ルートより上へは出ず、その上位の保存済み一覧へ戻る。
- 保存済み一覧を含めた選択画面の最上位で戻る：選択全体をキャンセルする。
- 「キャンセル」／Esc：現在の階層にかかわらず、選択全体をキャンセルする。
- 再生から開いた一覧をキャンセルしたときの戻り先は再生画面。ホームから開いた場合はホーム。
- 親へ戻ると、直前に出た子フォルダーを選択し、その位置を表示する。
- 保存済み一覧へ戻ると、直前に開いていた登録先を選択する。
- 一覧を閉じることと再生ウィンドウ自体を閉じることを区別する。後者は再生終了。

## 5. 入力ごとの共通割当

### 5.1 再生領域にフォーカスがある場合

| 操作           | キーボード   | TVリモコン                   | 直接タッチ         |
| -------------- | ------------ | ---------------------------- | ------------------ |
| 前のファイル   | ←            | 左方向                       | 右スワイプ         |
| 次のファイル   | →            | 右方向                       | 左スワイプ         |
| 10秒戻す       | ↑、Shift＋←  | 上方向、巻き戻し専用キー     | 左1/3をタップ      |
| 10秒進める     | ↓、Shift＋→  | 下方向、早送り専用キー       | 右1/3をタップ      |
| 再生／一時停止 | Space、Enter | 決定、再生／一時停止専用キー | 中央1/3をタップ    |
| ファイル一覧   | Esc、O       | 戻る                         | 画面の一覧ボタン   |
| メディア情報   | I            | INFOがあればINFO             | 画面の情報ボタン   |
| ホームに戻る   | H            | 画面のホームボタン           | 画面のホームボタン |

メディアの「再生」「一時停止」「前」「次」専用キーは、上表の意味に対応させる。キー長押しによるリピートで連続曲送り・連続シークを起こさない。1回の押下につき1回の操作とする。音量はOS・機器の音量操作を使用する。

### 5.2 ボタン・一覧・入力欄が対象の場合

操作の優先順位は「OS予約操作 → 入力中の文字・IME → 最前面のダイアログ／一覧 → フォーカス中の部品 → 再生領域」とする。

| 状態                    | 矢印                         | Enter／決定                      | Esc／戻る                                |
| ----------------------- | ---------------------------- | -------------------------------- | ---------------------------------------- |
| 再生領域                | 再生操作                     | 再生切替                         | ファイル一覧                             |
| 操作ボタンにフォーカス  | ボタン間の移動               | 選択したボタンを実行             | ファイル一覧                             |
| ファイル一覧のリスト    | 上下で項目、左右でページ移動 | フォルダーを開く／ファイルを再生 | Escはキャンセル。TV／Androidの戻るは親へ |
| 情報画面                | 情報内の移動・スクロール     | 選択中のボタン                   | 情報画面だけ閉じる                       |
| NASアドレスなどの入力欄 | 入力・カーソル移動           | 入力確定・接続                   | IMEや入力UIを先に閉じる                  |

- キーボードのTab／Shift＋Tabで部品間を移動する。
- 一覧のPage Up／Downは左右のページ移動と同じ。端で循環させない。
- ページ移動では、現在表示できる項目数を基準に移動し、次の選択行が見える位置へスクロールする。
- 文字入力中のI・O・H・Space・Backspaceなどを再生コマンドにしない。
- 一覧・情報画面の背後へ、矢印・決定・メディアキーを伝えない。
- 一時停止後のTV操作は自動的に再生ボタンへフォーカスするため、矢印がUI移動に変わる。画面上の案内も同時に切り替える。
- フォーカス中のボタンは枠・色・読み上げで識別できるようにする。

キーボードでも、ボタンにフォーカスを移した後は矢印をUI移動に使う。Windowsだけ停止中の矢印を常に再生操作にする例外は設けない。

### 5.3 タッチとダブルタップ

対象：Android、iOS、iPadOS、Windowsの直接タッチ。

- 3分割タップは、操作ボタン・情報パネルを除いたメディア表示領域に適用する。音声のみの場合は中央のメディア領域を使う。
- 右スワイプは前、左スワイプは次。
- 1回のスワイプをタップとしても処理しない。
- スワイプは横移動70論理単位以上、横移動が縦移動の1.5倍以上を初期基準とする。pxではなくdp／pt／DIPで判定する。速度の必須条件は設けない。
- 同じ領域・近い位置への300ms以内のダブルタップは、1回分の操作とする。右側なら合計＋10秒、中央なら切替1回。
- 単タップの応答を優先し、初回で実行済みならダブルタップの2回目で追加実行しない。
- 300msの基準と許容距離は実機で調整し、7環境の共通受入条件として管理する。OSのアクセシビリティ入力設定を尊重する。
- 2本目以降の指や、ピンチを前後移動に誤認しない。

### 5.4 マウス・トラックパッド

対象：Mac Catalyst、Windows、iPadOS、ポインターを利用するAndroid等。

| 入力                            | 動作                           |
| ------------------------------- | ------------------------------ |
| 再生領域の背景を1回クリック     | 位置にかかわらず再生／一時停止 |
| 前後・±10秒ボタンをクリック     | 対応する操作                   |
| ファイル行を1回クリック         | 0秒から再生                    |
| フォルダー行を1回クリック       | フォルダーを開く               |
| 一覧のホイール・2本指スクロール | スクロール                     |
| 登録先を右クリック              | 登録解除等のメニュー           |

- ポインターの背景クリックを左右3分割にしない。画面上の直接タッチとは区別する。
- ダブルクリックで全画面化しない。再生切替も1回分として処理する。
- ホイールや2本指スクロールで再生位置・音量・ファイルを変えない。
- ポインターのドラッグをファイル送りジェスチャーにしない。
- 非アクティブなウィンドウの最初のクリックはフォーカス取得に使用し、同時に再生操作を実行しない。
- トラックパッドによるポインター操作はこのルールを使い、タッチ画面への直接入力とは区別する。
- Mac Catalyst, Windowsの全画面表示ではポインターが3秒間動かないと非表示になる、非表示状態でマウスやトラックパッドを使用すると再表示する。

### 5.5 tvOSリモコンのタッチ面

tvOSのリモコン面は「方向入力」として扱う。左方向のスワイプは←相当の前、右方向は→相当の次とし、方向ボタンを押したときと一致させる。上下も方向ボタンと同じ10秒シークに揃える。

これは画面を直接触ってコンテンツを送るスワイプとは異なる入力として明記する。直接タッチの左スワイプ＝次と、リモコンの左方向＝前を同じ説明図に混在させない。リモコン上の絶対タッチ位置を画面3分割タップに対応させない。

1回のリモコン操作がスワイプと方向イベントの両方として届いても、1回だけ実行する。フォーカスがボタンや一覧にある間は、同じ入力をそのUIの移動に使用する。

### 5.6 OSの予約操作

ホーム、電源、音量、OSの画面切替等をアプリ内操作に上書きしない。tvOS／Android TVのホームボタンとアプリ内の「ホームに戻る」は別物として扱う。

## 6. 再生の境界と終了

| 条件                             | 共通動作                                                   |
| -------------------------------- | ---------------------------------------------------------- |
| 前／次のファイルへ移動           | 移動先の0秒へ。再生中なら再生、一時停止中なら一時停止      |
| 最初のファイルで前               | 移動しない。前ボタンを無効化                               |
| 最後のファイルで次               | 移動しない。次ボタンを無効化                               |
| 10秒戻すと0秒未満                | 0秒へ。前のファイルには移動しない                          |
| 10秒進めると末尾以上、次あり     | 次ファイルの0秒へ。元の再生／一時停止状態を維持            |
| 10秒進めると末尾以上、次なし     | 現在位置を維持。移動しない                                 |
| 長さ不明でシーク可能             | OS／再生エンジンが確定できる範囲で移動。推測で曲送りしない |
| シーク不可                       | シークボタンを無効化。キー入力でも移動しない               |
| 自然にファイル末尾へ到達、次あり | 次ファイルへ自動進行                                       |
| 自然に最終ファイル末尾へ到達     | 終了状態。操作部と「最後まで再生しました」を表示           |
| 終了状態で再生                   | 最終ファイルの0秒から再生                                  |

リピート・シャッフル・クロスフェードは今回の共通操作要件に追加しない。ファイル一覧のメディアは同じフォルダー直下を対象とし、サブフォルダーは自動連続再生に含めない。

## 7. 割り込み・復帰・全画面

### 7.1 中断の扱い

| 対象                  | 再生を維持する                                                         | 一時停止し、復帰後は手動再開                           |
| --------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| Android               | 回転、サイズ変更、表示中の複数ウィンドウでのフォーカス移動             | バックグラウンド、ロック、再生割り込み                 |
| iOS                   | 回転・アプリ内画面の表示調整                                           | バックグラウンド、ロック、再生割り込み                 |
| iPadOS                | 表示中のシーンから他アプリへの入力フォーカス移動、ウィンドウサイズ変更 | シーンのバックグラウンド、ロック、再生割り込み         |
| Android TV・tvOS      | アプリ前面での操作部の表示切替                                         | TVホーム、他アプリ、スリープ、再生割り込み             |
| Mac Catalyst・Windows | 他アプリへのフォーカス移動、ウィンドウ移動・サイズ変更、全画面切替     | 最小化、明示的な非表示、ロック、スリープ、再生割り込み |

- 使用中の音声出力機器の切断でも一時停止し、手動再開とする。
- 復帰時は元のファイル・秒数を表示し、操作部を出す。
- 一覧・情報表示中に割り込みがあった場合、その後のキャンセル／閉じるでも自動再開しない。
- 非アクティブになったという通知だけで一律停止せず、表のユーザーに見える状態へ対応づける。
- アプリ終了・プロセス破棄後はホームから開始。秒数の永続復元は本案の必須要件に含めない。

### 7.2 全画面

- Android／iOS／iPadOS／TVは、利用可能な再生表示領域を使用し、OSが許す範囲でシステムUIを隠す。
- Mac Catalyst／Windowsは、再生開始時に現在のウィンドウ／全画面状態を維持する。Windowsだけ自動全画面にしない。
- デスクトップの全画面切替ボタンを提供し、WindowsはF11、Macは標準の全画面操作を補助入力として使用する。
- 再生画面のEscはファイル一覧を開く。全画面を解除したい場合は全画面ボタン・対応ショートカットを使う。
- OSが優先してEscを全画面解除に使う状態ではOSを優先し、同じ押下で一覧も開かない。
- 全画面解除・回転・リサイズで再生位置、プレイリスト、再生状態を変えない。

## 8. 保存済みフォルダーと追加

### 8.1 共通の流れ

ホーム → 保存済みフォルダー → フォルダーを追加 → 保存先選択 → フォルダー登録 → 保存済みフォルダー → ファイル一覧 → 再生

- 保存済みが0件でも1件でも、この流れを維持する。0件なら追加ボタンを主操作にする。
- 登録直後は保存済み一覧に戻り、登録した項目を表示・選択する。
- 登録だけでは再生しない。重複登録では既存項目を更新して選択する。
- 標準ピッカーのキャンセルは保存先選択へ、追加全体のキャンセルは保存済み一覧へ戻る。
- 「フォルダーを追加」の保存先選択画面には、キャンセルと重複する「保存済みフォルダー」ボタンを設けない。キャンセル・戻る・Escで保存済み一覧へ戻る。フォルダー階層の閲覧画面では親移動を維持する。
- 再生中の一覧から追加した場合も、元の再生セッションは保持する。

### 8.2 保存先の違い

| 対象         | 保存先                                             |
| ------------ | -------------------------------------------------- |
| Android      | OSが公開する端末／外部ストレージ、DLNA             |
| Android TV   | 利用可能なOSフォルダー選択、USBブラウザー、DLNA    |
| iOS・iPadOS  | OSファイル画面が公開する端末／外部ストレージ、DLNA |
| tvOS         | DLNA。ローカル／USBは今回の必須要件に含めない      |
| Mac Catalyst | Macの標準フォルダー選択、DLNA                      |
| Windows      | Windowsの標準フォルダー選択・ドライブ、DLNA        |

利用できない保存先は追加画面に表示しない。OSの権限画面へ進む前に、何のために選ぶのかを短く説明する。

### 8.3 登録解除

全対象で、保存済み行の補助メニューボタンとポップアップメニューは設けない。行の長押し（TVでは決定キーの長押し）で登録解除の確認画面を開く。ポインターの右クリックでも同じ確認画面を開ける。DeleteやiOS系のスワイプを追加の操作として提供する場合も、確認を経て解除する。読み上げでは行の長押しアクションに「登録解除」の名称を付ける。

「登録を解除しますか？ ファイルは削除されません。」と確認する。接続先がオフラインでも解除できる。解除後は次の項目、なければ前の項目、0件なら追加ボタンへフォーカスを戻す。

実ファイル削除機能は設けない。

## 9. 一覧の表示・応答

- ファイルとフォルダーのアイコンを分け、右端の階層矢印はフォルダーだけに表示する。
- メディア名末尾の既知の対応拡張子は一覧で省略する。DLNAタイトルにも同じ表示処理を適用し、途中のピリオドは消さない。
- 拡張子省略で同名になる行は、その行に形式バッジを付けて識別できるようにする。
- ファイル選択ダイアログに「名前・形式」ボタンを設けず、ファイル行の長押し（TVでは決定キー長押し）・右クリックでもメディア情報を開かない。これらの操作でファイルの再生も開始しない。保存済みフォルダー行の長押し・右クリックによる登録解除（8.3）は維持する。元の名前・形式などの詳細は、再生を一時停止して「メディア情報」から確認する。形式バッジ、ツールチップ、読み上げによる項目の識別は維持する。
- 通常は最大2行。高さが限られる横長画面は1行表示を許可する。長い名前の全文はツールチップや読み上げ、再生画面のメディア情報で確認できる。
- フォルダー優先、メディアはOP／ED順、季節フォルダーは年・冬春夏秋順。自然言語の照合順までOS間で完全一致させることは本案の必須要件にしない。
- 一覧移動・再読込中は既存のタイトル、行、スクロール位置、画面サイズを維持する。
- 取得が0.5秒を超えたら読み込み表示を重ねる。新規の初回表示は読み込み状態から開始してよい。
- 取得中は古い行の決定・登録・追加要求を無効化し、キャンセルだけは常に使えるようにする。
- 取得中の戻るは一覧全体のキャンセルとし、要求を中断する。キャンセル後の遅延応答で画面を開き直さない。
- ファイル選択後は黒い再生面を用意してから一覧を閉じ、途中でホーム画面を挟まない。

## 10. DLNA接続・情報・エラー

### 10.1 DLNAの共通動線

全対象で「サーバー一覧」と「アドレスを指定して接続」を用意する。自動探索は利用できる環境でのみ実行する。探索できない環境でも、同じ画面から手入力できるようにする。

- 自動探索できない場合は「この環境ではアドレスを入力して接続してください」と表示する。
- 検索中でも手入力・キャンセルへ進める。
- 手入力欄・接続結果・再試行の用語を共通化する。
- 接続できない登録先は自動削除しない。
- ファイルの形式対応は別途機能表に明示する。本案の採用だけでApple系のDLNA音声対応やSSDP権限を実現したとは扱わない。

### 10.2 メディア情報

「ファイル」「映像・音声形式」「音声出力」の順に表示する。取得できない値は「取得できません」、機能自体がない項目は「未対応」と区別する。

情報表示は一時停止して元の状態を保持する。閉じたときは一覧キャンセルと同じ復元ルールを使い、表示中に割り込みがあれば手動再開とする。I／Esc／戻るは情報画面だけを閉じ、背後のファイル一覧を同時に開かない。

### 10.3 エラー

再生失敗は全対象で一時停止し、ファイル名・理由と、次の操作を表示する。自動スキップは行わない。

- 再試行：同じファイルを最後に確認できた秒数から再試行。開始前の失敗なら0秒。
- 次のファイル：次がある場合のみ表示。明示操作として0秒から再生する。
- ファイル一覧：元のフォルダーを開く。
- 閉じる：エラー表示だけ閉じ、一時停止状態を維持する。

権限失効・USB取り外し・通信断では、再許可／再接続の案内を優先する。同じ失敗を無限に自動再試行しない。エラー表示中のフォーカスは再試行か、実行可能な最初の操作に合わせる。

## 11. ホーム・アプリ終了・保存

- 「ホームに戻る」は確認なしで再生を終了し、ホームへ戻る。ファイル一覧のキャンセルと明確に区別する。
- アプリの終了は全プラットフォームでOSに任せる。ホーム・再生ツールバーにアプリ内の終了メニュー・終了ボタンを置かず、アプリ独自のタスク削除は行わない。
- ホームの操作ボタンは「OP / EDを選ぶ」のみとし、終了用の「その他」ボタンを設けない。
- 保存済みフォルダー行の補助メニューボタンも設けず、登録解除は8.3の長押し操作から行う。
- Mac／WindowsはOS標準のウィンドウを閉じる・アプリ終了を使用する。
- ホームからのAndroidの戻る等はOSの通常動作へ渡す。
- 登録先と必要な権限を保存する。直近の一覧選択は同じセッション中に復元する。
- アプリ再起動後の自動再生、再生秒数・キューの永続復元は今回導入しない。起動時はホーム。

## 12. 7環境への適用と移行優先度

| 環境         | 主に変更・確認する点                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Android      | 一覧表示でプレイヤーを破棄しない。スマホの戻るも一覧へ。単一SAF省略を廃止。画面内キー案内の逆転を修正                    |
| Android TV   | 一覧キャンセルで位置・再生意図を復元。操作部のフォーカス規則と表示案内を一致させる                                       |
| iOS          | 一覧キャンセルを元の再生意図へ復元。選択確定は常に自動再生。情報表示の復元ルールを統一                                   |
| iPadOS       | iOS共通仕様に加え、キーボード・ポインター・表示中のフォーカス移動とバックグラウンド化を区別                              |
| tvOS         | 戻る1回で一覧へ。方向タップと方向スワイプを同じ意味に。選択・キャンセル・情報の状態復元                                  |

| Windows      | 一覧でセッションを保持。非アクティブだけで停止しない。自動全画面を廃止。ダブル入力抑制、拡張子省略、フォーカス規則を統一 |

### 段階導入

1. **第1段階：動作の意味** — 一覧・選択・キャンセル・戻る、方向キー、TVフォーカス、案内文を統一。
2. **第2段階：応答と中断** — ダブルタップ、スワイプ、割り込み、情報・エラー、全画面を統一。
3. **第3段階：選択画面** — 登録動線、表示名、読み込み中の一覧維持、DLNA手入力を統一。
4. 配色・字体の微調整は、上記の操作が揃ってから行う。

## 13. 共通受入シナリオ

次のシナリオを、7環境の各対応入力で確認する。ビルド成功だけで操作感の統一を完了としない。

1. Aを30秒まで再生 → 一覧 → 別フォルダーへ移動 → キャンセルでAの30秒付近から再開。
2. Aを30秒で一時停止 → 一覧 → キャンセルで30秒付近の一時停止を維持。
3. 一覧表示中にロック／スリープ → 復帰 → キャンセルで元の位置に戻るが再開しない。
4. 一時停止中でも同じA・別のBを選択すると、選択先の0秒から再生。
5. 再生領域で左右＝前後、上下＝±10秒。ボタン・一覧・文字入力ではそのUIを優先。
6. TVで一時停止すると再生ボタンにフォーカス。決定で再開して再生領域へ戻る。
7. TVで方向ボタン・タッチ面の同方向操作が同じ結果になり、1回の入力を二重処理しない。
8. 右側ダブルタップは合計＋10秒。中央ダブルタップは切替1回。ポインターも二重切替しない。
9. 先頭の前、末尾の次、0秒手前、末尾をまたぐ10秒シークが第6章どおり。
10. 保存済み0件・1件・複数件で同じ入口を使い、登録後は登録した行に戻る。
11. 再生中に回転・リサイズ・全画面切替・入力機器切替を行っても再生状態を維持。
12. Mac／Windowsで別アプリへフォーカスを移しても継続し、最小化・ロック後は手動再開。
13. NAS／USBを切断すると原因と次の操作を示し、登録先を勝手に削除しない。
14. 読み込み中にキャンセルすると即座に閉じ、遅れて完了した要求が画面を戻さない。
15. フォーカス・スクリーンリーダーだけで一覧・再生・情報・キャンセルへ到達できる。

タイミング判定、フォーカスの見やすさ、TVでの距離・サイズ、ネットワーク切断時の位置復元は実機調整項目とする。本案で定めた結果を変える場合は、OSごとに例外を増やす前に共通仕様を改訂する。
